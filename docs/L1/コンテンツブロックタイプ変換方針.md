## ブロック要素

- 通常本文
    - 標準

- 見出し
    - 標準

- リスト（通常、数字）
    - 標準

- 区切り装飾線（dot-line-brown）
    - 標準区切り線

- 引用
    - 標準

- テーブル
    - 横幅カスタム
        - なくす、標準テーブルのみ採用
        - 後日見つけたので追記：Notion のテーブルには「幅にあわせる」という設定があるが、API にはないので使えない（いつか期待！）
    - ミニテーブル 
        - 例外っぽいものはすでに全部排除したので標準テーブルにする

- コードブロック
    - 標準
    - 言語渡せる！！！

- 画像
    - 標準
    - キャプションつきも標準のキャプションをつかう

- ブログカード
    - 内部/外部ともに既存のショートコードを Notion の Web ブックマーク (`/bookmark`) に変える

- X ポスト（角括弧なしのただの URL 段落 (x.com or twitter.com)）
    - Notion ではツイート埋め込みを使う
    - Nuxt 側では新 Static tweet block を使う

- 汎用ブロック
    - info ブロック
        - Notion のコールアウト（絵文字：💡）
    - 追記ブロック
        - Notion のコールアウト（絵文字：♻️）
    - 警告ブロック
        - Notion のコールアウト（絵文字：🚨）

- 枠ボックス
    - Notion のコールアウト（絵文字：なし）

- 数字リストブロック
    - 廃止して waku-common で単なる ol を囲むスタイルにしておいた

- ボタン
    - 新規ショートコード: `[button text="" url="" color="{xxx|yyy|zzz}"]`
    - Notion のボタンは Block API で unsupported になってしまうので採用できなかった

- 小さい文字の画像キャプション
    - いま `micro-bottom` クラスがついている `<div>` の直前の要素は必ず画像になっているので、その画像に Notion 標準のキャプションをつければよい

- アプリ紹介カード
    - 新規ショートコード: `[app name="" icon="{fileName}" developer="" price="" (ios="url") (android="url")]`
        - 細かい各データはアプリーチ取ってきて HTML にしていたもので、アプリーチに API などがない以上そのまま移行はできない
        - Notion にはマークアップごと保存できないので、移行時に元 HTML からすべて焼き込むことにした（103 件）
            - アイコンは Google / Apple の CDN 直リンクだと将来切れるため、webp に変換して mirumi.media に置いた
    - 今後の新規記事は iTunes Search API（認証不要・無料）を使って `ios` の URL だけから組み立てる
        - Google Play には公式 API がないので Android 単体のアプリは今後基本扱わないのが前提、まあいけるっしょ

- iframe 埋め込み
    - 残りはすべて YouTube
        - Notion の動画埋め込みを使う
        - Nuxt での置換先はいまの遅延読み込みのやつみたいに普通の iframe にすればよい

- YouTube 遅延読み込み
    - 新規ショートコード: `[video delay src="url" thumbnail="url" (ts="23s")]`


## インライン系

- インライン span
    - フォントサイズ系（すでにすべて下記 4 つに正規化済み）
        - 0.8em: `{\scriptsize\text{小さい文字}}`
        - 1.35em: `{\large\text{文字}}`
        - 1.5em: `{\Large\text{文字}}`
        - 2.0em: `{\LARGE\text{文字}}`
        - この中にリンクがあると同居できないため、リンクを残して文字サイズのほうを捨てる（残り該当 32 件）
            - 捨てたときは `font_size_dropped` の警告を出すので dry-run で追える
    - 色系
        - 赤
            - 標準
        - 青
            - color-blue があと 2 記事だけ残ってるがこれは正式に青色標準に置換する
        - グレー
            - color-gray を新設する。ライトテーマでは #999999、ダークテーマでは #808080 にする
                - いまの移管もととしては上記どちらもそのまま残してあります
    - 背景色系
        - 全部廃止
    - underline
        - 全部なくした
    - 残りのもの
        - すべてチェックして可能な限り正規化した
        - 残りは `tools/migrate-to-notion/blog-content-block-survey/span.csv` を参照のこと

- `<del>`
    - 標準

- `<code>`
    - 標準

- `<em>`、もしかしたら `<i>` もあるかも
    - 標準（斜体）

- `<sup>`, `<sub>`
    - 標準（インライン数式）

- `<span class="keyboard-key">`
    - 廃止：これはもう全部 `<code>` に変わってる
        - が、別に今後の本文では `<code>` すらなしで普通に Enter とか書けばいい説しか思わなくなった！

- 1px 画像
    - これは全部消した


## ショートコード

- `[audio` から始まるもの
    - Notion の音声埋め込みにする
    - クロージングタグがあるのでなくす
    - `preload="none"` にする（再生するまで一切ダウンロードしない）

- `[video` から始まるもの
    - Notion の動画埋め込みにする
    - クロージングタグがあるのでなくす
    - `preload="metadata"` にする（本体は落とさず、寸法と尺だけ読んでレイアウトのガタつきを防ぐ）

- `[amazon` から始まる商品リンクはそのまま持っていく
    - rakuten は既存記事ではゼロにした
    - 形式は `[amazon asin="{10桁ASIN}" kw="{検索語}" title="{API 取得失敗時の表示名}"]`
        - `asin`、`kw`、`title` はすべて必須
        - 既存 538 件の `size` はすべて `l` で Nuxt 側では使っていないため、最終移行時に削除して今後も廃止する
        - 商品情報は Amazon Creators API から取得し、API 取得失敗時だけ shortcode の属性による画像なし card を表示する

- 残ったものがブログカード
    - それ以外の雑多なショートコードやショートコードですらないものはすでに消してある
    - ショートコードと機能するべきものでインラインのものは残っていないはずなので `<p>[xxx` で探す→単に標準テキストでそのまま置き換えればいい（`/` 始まりもなるべくフル URL にしたいが）
        - p じゃなくて div で囲まれているものもあるっぽいので注意！
        - ソースコード内のものも `[]` の文字列は残ってるけどこれはオンリー段落じゃないから大丈夫なはず
        - あと途中で `[]` を撲滅する作業はやめたから文中の普通の文字列として使われているやつはまだ残っているから注意してね
    - URL は今回を機にフルパス表記のみとする（`/android-app` とかはだめ）


## 例外系

- 埋め込み css
    - `カスタム CSS` プロパティに直接 css を書けばいい（ただしもともとレンダリングされる class にしかもちろん使えないけどね）

- 漫画画像の引用表現（/comic`、/yakuneba）
    - 新規ショートコード: `[quoteImage name="{filename}" copyright="" (width="")]`
        - `width` は `[image]` と同じく表示幅の指定。WordPress のエディタで変えた幅も移行時にここへ持ち込む


## その他

- Search Regex でミスって標準テキスト段落なのに p タグで囲まれていないものがけっこうありそうなので考慮して（少なくとも今回もうやった）

- 画像のサイズ調整
    - 画像そのものは Notion 標準の image ブロックにする（ショートコードにしちゃうと画像自体をそもそもどうやっても同期できない）
    - 見た目の指定は image ブロックのキャプション先頭に `[image (width="") (align="") (alt="")]` の形式で書く
        - ショートコードより後ろが本来のキャプション、ショートコードと実キャプションの間は半角スペース 1 個で区切ることとする
        - 指定が何もない画像にはショートコード自体を置かない
        - 実キャプションが `[image` で始まることはないので、この形なら先頭だけ見て判別できるという考え方
        - `alt` は Notion の image ブロックに alt 属性がないからで、ファイル名から復元できないものだけを持ち込む
            - Notion API は本文 image block の元 filename も返さない。signed URL からも復元できず意味のある alt が必要な画像では、この `alt` を明示する
    - インライン画像（段落の途中に置かれていて image ブロックにできないもの）だけは `[image name="{fileName}" …]` のショートコードのまま本文に残す
        - これによって既存画像の表現の移行はできるが、Notion 移行後は新たにインライン画像を置くことは現実的にできなそうなので制限事項として呑む
            - （すごい回りくどいことすればポインタ的に実体だけ別のところに置くとかできそうとも言われたが一旦忘れる）

- 画像の枠線なし指定の `.sss`
    - これは今回をもって画像のデフォルトの枠線含めて廃止とする！
    - 既存コンテンツの `.sss` クラスは残しておくけど、フロントエンドからはこのスタイリングをなくし、今後もとくに新規でなにかすることはできないということにする

- a タグで囲まれている画像は Notion では表現方法がないので洗い出してなんとかする必要がある
    - なにもしなければ自動的に（リンクが）消えるらしいのでとくに気にしなくてよい
