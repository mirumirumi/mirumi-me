
# サイト変更オペレーション手順

- [x] Route53にmirumi.meのホストゾーンを作成する

- [x] GoogleDomain上でmirumi.inをConoHaに転送させるようにする
    - 今回はConoHaへの転送はカスタムネームサーバーを使うことにする

- [x] mirumi.inにドメインつけたらfetchのbaseURLを修正する
- [x] mirumi.inにドメインつけたらCIのところコメントアウト解除する（特定記事のre-generateのほうも！）
- [x] mirumi.inにドメインつけたら拡張機能のエンドポイント先を変える

- [x] mirumi.meのWordPressディレクトリをまるっとmirumi.inディレクトリにコピーする

- [x] mirumi.in側のWordPressのサイトURLをmirumi.inに変更する
    - [x] mirumi.inのWordPressサイトはnoindexにする
    - [x] この時点でAPIアクセスが正常稼働しているか確認する

- [x] 最新のコンテンツをデプロイする

- [x] Googleドメインでmirumi.meのドメインをカスタムネームサーバーでRoute53のホストゾーン上のNSに変更する
- [x] ACMを立てて証明書のインストールを完了させる
- [x] CloudFrontのviewer_certificate部分を書き換え、カスタムドメインの紐づけを完了させる
- [x] CloudFrontに転送できるようにAレコードをつくる

- 確認系
    - [x] ConoHaのassetsディレクトリを削除して（開発/本番ともに）問題ないことを確認する
    - [x] サイトガードのログインページチェンジを元に戻す
    - [x] 全デバイスで確認する
    - [x] サイトマップ類の確認
        - [x] 下層も送ってみる
    - [x] シェアカウントのチェック
    - [x] 外部ブログカードのサムネキャッシュが正しく表示されていることを確認する
    - [x] アドセンスが全て表示されていることを確認し、marginの調整を行う
    - [x] トップ含む主要なページをインデックスリクエストしまくる
    - [x] 記事内にあるダウンロード系ボタンのリンク先をmirumi.mediaになっているか確認
    - [x] mil-light.milmemo.netのリンクをリダイレクトできているか確認
