# バックアップからの復旧手順

定期バックアップの仕組みは `Notion 公開基盤運用手順.md` の「定期バックアップ」を参照。
ここは「壊れたあとに何をするか」だけを書く。

## まず状況を見分ける

| 壊れたもの | やること |
| --- | --- |
| サイトの配信物だけ（Notion は無事） | full build を回す。バックアップは要らない |
| 記事 1 本を Notion で消した / 壊した | Notion のページ履歴から戻す。30 日以内ならこれが最速 |
| データソースごと消えた、30 日を過ぎた | 以下の復旧手順 |

Notion 自体の自動保存が 1 段目で、バックアップは**それを超えたとき**の手段。
いきなり S3 を掘る前に Notion の履歴を見る。

## バックアップを選ぶ

`manifest.json` だけは S3 でも Standard なので、すぐ中身を読める。

```bash
aws s3 ls s3://mirumime-prd-backup/v1/
aws s3 cp s3://mirumime-prd-backup/v1/<日時>/manifest.json -
```

`manifest.json` があればその回は完走している。`files` の `count` が記事数や
コメント数として妥当かを見て、どの日付から戻すかを決める。

## 中身を取り出す

R2 のほうが速い。R2 が使えるならこちらだけでよい。

```bash
cd server
bunx wrangler r2 object get mirumi-me-backup-prd/v1/<日時>/notion-posts.ndjson.gz \
  --file notion-posts.ndjson.gz --remote
sha256sum notion-posts.ndjson.gz  # manifest の値と一致すること
```

S3 側は Deep Archive なので、先に復元をかけて**12 時間ほど待つ**。

```bash
aws s3api restore-object --bucket mirumime-prd-backup \
  --key v1/<日時>/notion-posts.ndjson.gz \
  --restore-request '{"Days":7,"GlacierJobParameters":{"Tier":"Standard"}}'
# head-object の Restore が ongoing-request="false" になったら取得できる
aws s3 cp s3://mirumime-prd-backup/v1/<日時>/notion-posts.ndjson.gz .
```

## Notion へ戻す

`notion-*.ndjson.gz` は 1 行 1 row で、`{ page, blocks }` の形。`page` は
`pages.retrieve` の応答そのもの、`blocks` は Block API の応答を親子でネストした木。
復元専用のスクリプトは用意していないので、そのつど次の流れで書く。

1. `notion-data-sources.json` の schema で空のデータソースを作り直す
2. 各行の `page.properties` を `pages.create` の形に直して投入する
3. `blocks` を根から `blocks.children.append` していく（子は親を作ってから）

property をそのまま渡せない点に注意する。

- `formula` / `button` / `rollup`（`status`、`プレビュー`、`公開`、`非公開`、`開くボタン`）は
  書き込めない。データソース側の定義として作り直す
- `last_edited_time` / `last_edited_by` / `created_time` / `created_by` は Notion が決める。
  作成日時や編集者は復元できない
- `relation`（`category`、コメントの `親コメント`）は**参照先を先に作ってから**、新しい page ID で張り直す
- `files`（`thumbnail`）の URL は失効している。`mirumi.media` にある canonical URL なら
  external file として張り直せる

property ID は schema を作り直すと変わるので、`server/wrangler.jsonc` の
`NOTION_*_PROPERTY_ID` と `NOTION_*_DATA_SOURCE_ID` を新しい値へ更新する。

## サイトを戻す

Notion が戻ったら full build を 1 回回せば、配信物と publish index は作り直される。

Notion の復旧を待たずにサイトだけ先に戻したいときは `published-pages.ndjson.gz` を使う。
1 行 1 記事で、`page` が配信された時点の `BuildPage`（レンダリング済みの `contentHtml` と
焼き込み済みのコメントを含む）。これを build manifest の `articles/<pageId>.json` として
並べれば、Notion を読まずに `nuxt generate` できる。`publish-index.json` は
`_internal/publish-index-v1.json` へ戻せばそのまま publish index になる。

ただしこれは**配信物を作り直すための材料**であって、Notion の正本ではない。
下書きや非公開記事は含まれないので、最終的には Notion 側の復旧が要る。
