# 用語集

リリースと公開まわりで docs とコードに出てくる言葉の意味をまとめる。
名前をこう決めた理由は `docs/L2/Notion 公開基盤の設計.md` の「用語」。

## リリース

| 用語 | 意味 |
| --- | --- |
| deploy | `wrangler deploy`。Worker をその場で新しいコードに切り替え、続けて Container image を build / push して rollout を始める。Worker と Container image はいつもまとめて出る |
| rollout | 動いている Container instance を、新しい image のものに入れ替えること。deploy のコマンドが終わったあとも数分続く。入れ替え中に起動した instance は途中で止められる |

## サイトの生成と公開

publish の Workflow（`mirumi-me-publish-<env>`）は、次の 3 つを `mode` で切り替えて動かす。

| 用語 | `mode` | 意味 |
| --- | --- | --- |
| generate | `full` | 今 deploy されているコードで、公開中の全記事からサイト全体を作り直して配信する。Notion の公開状態は変えない。470 記事で 35 分から 1 時間 |
| bootstrap | `bootstrap` | 初回だけの generate。Notion の `last-deploy` も初期化する。publish index があると実行できない |
| 公開（partial publish） | `partial` | 記事ごとに公開・非公開の状態を変える。Notion の `公開` / `非公開` ボタンから動く。1 本 1.5 分から 4 分 |

- 公開状態を変えるのが公開（publish）、変えずに作り直すのが generate
- 手元から generate を流すときは `bun run generate:dev` / `bun run generate:prd`

## そのほか

| 用語 | 意味 |
| --- | --- |
| コメント反映（comment refresh） | コメントの承認や返信を、その記事のページに反映する。別の Workflow（`mirumi-me-comment-refresh-<env>`）で動く |
| Nuxt generate | Container の中で動く `nuxt generate` コマンドそのもの。generate でも公開でもコメント反映でも動く。上の generate と区別したいときはこう書く |
| publish index | S3 の `_internal/publish-index-v1.json`。最後に公開できた各記事の状態を持ち、slug の持ち主を記録する |
